SECTION 8 — SVG DIAGRAM RULES
══════════════════════════════════════════════════════════════════

Every SVG must:
1. Have a unique subject — no two SVGs in the same batch may show the same type of system
   (e.g. one water filtration, one greenhouse ventilation, one circuit, one anatomical cross-section —
   never two water systems, never two flow diagrams of the same domain).
2. Be technically accurate for its subject — components, flow direction, labels must reflect
   how the real system actually works.
3. Use a clear visual hierarchy: background rects for containers, arrows for flow direction,
   bold labels for main components, small numbered circles (⓪①②) for blank positions.
4. viewBox must be large enough: minimum 500 × 340.
5. Use these SVG elements: rect, circle, line, polyline, path, text, g, defs, marker (for arrowheads).
6. Define arrowhead markers in <defs> so flow lines have visible arrow tips.
7. Numbered blank positions must be drawn as a white filled circle with a black stroke
   and the number inside, positioned exactly at the part of the diagram being labelled.
8. Every component that has a question blank must have a clearly drawn connector line
   from the component to its numbered circle.
9. Colors: use light fills (#e8f4fd for liquid, #fff9e6 for gas, #f0ffe0 for biological,
   #f5f5f5 for structural) and dark strokes (#333). Labels in #222.
10. The SVG value must be a single-line string with no line breaks inside — escape all
    double quotes as \" and do not use single quotes inside attribute values
    that are already wrapped in single quotes in the JSON.

SECTION 9 — UNIVERSAL QUALITY RULES
══════════════════════════════════════════════════════════════════

UNIQUENESS
- Across all banks in the batch: topics, vocabulary clusters, passage themes, and SVG subjects
  must all be distinct. Plan all topics before writing any question.
- No bank may reuse a word cluster from another (e.g. if one bank is about glaciers,
  no other bank may use polar, ice, melt, arctic, tundra as core vocabulary).

ANSWER INTEGRITY
- Completion type answers (SENTENCE_COMPLETION, NOTE_COMPLETION, TABLE_COMPLETION,
  FLOW_CHART_COMPLETION, SUMMARY_COMPLETION, SHORT_ANSWER) must be words or phrases
  that appear verbatim in the passage. If the passage does not contain the answer, rewrite
  the passage until it does — never write a question whose answer is absent from the passage.
- TFNG: "TRUE" means the passage explicitly confirms it. "FALSE" means the passage explicitly
  contradicts it. "NOT_GIVEN" means the passage neither confirms nor contradicts it.
- YNNG: same logic but for the writer's opinion/claim rather than factual content.

MATCHING GROUPS
- Every question in a MATCHING_HEADINGS, MATCHING_INFORMATION, MATCHING_FEATURES, or
  MATCHING_SENTENCE_ENDINGS group must carry the full identical options array.
- Only the isCorrect flag differs per question within the group.
- Options list must contain more choices than questions (at least 2 distractors).

INSTRUCTIONS FIELD
- Write the exact instruction the student sees, matching real IELTS wording, e.g.:
  "Choose NO MORE THAN TWO WORDS from the passage for each answer."
  "Do the following statements agree with the information in the passage? Write TRUE, FALSE or NOT GIVEN."
  "The passage has six paragraphs A–F. Which paragraph contains the following information?"
  "Complete the notes below. Choose NO MORE THAN TWO WORDS from the passage for each answer."
  "Complete the flow chart below. Choose NO MORE THAN TWO WORDS from the passage for each answer."
  "Label the diagram. Choose NO MORE THAN TWO WORDS from the passage for each answer."

OUTPUT FORMAT
- Output ONLY the JSON object. No markdown. No code fences. No preamble. No postamble.
- The very first character must be { and the very last must be }.
- Use UTF-8. Preserve em-dashes (—) and other Unicode characters as-is.
- Do not truncate. If the output would be cut off, produce fewer sets and state so
  ONLY as a JSON comment at the very end after the closing } — never truncate mid-object.
